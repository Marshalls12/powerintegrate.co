Why this tool

Built for fast inspection, not heavy analysis.

Most parquet viewers are either desktop apps that need installing, cloud services that want your file uploaded, or notebooks that need a Python environment. This sits between all of them.

01
Local-only parsing
Your file is read by JavaScript in your browser tab. It never touches a server, never hits a log, never leaves your machine. Safe for production data, PII, and files you cannot upload.
02
Metadata first
See row count, row groups, compression codec, writer, and format version before you look at a single row. The things that tell you whether a file was written correctly.
03
Typed schema view
Physical types, logical types, and repetition rules displayed side by side. Catches schema drift before it hits your Power BI model or your dbt test.
04
Paginated row browsing
Reads only the page you are viewing using row-group offsets. Open a large file without waiting for a full load or melting your browser tab.
05
Filter and export
Substring filter across every column for quick spot checks. Export the whole file or just the filtered rows to CSV with one click.
06
Zero setup
Bookmark the page. No npm install, no Python env, no desktop app, no account. Works on any modern browser on any OS.

Technical notes

What it supports.

Compression
SNAPPY, GZIP, ZSTD, LZ4, BROTLI, uncompressed
File sources
Local files via drag-and-drop or file picker. Files are read as browser File objects with streamed byte ranges.
Pagination
100 rows per page using byte-range reads. Page navigation does not re-read the whole file.
Filter
Client-side substring match, case insensitive, across all columns. Available for files up to 200,000 rows.
Nested types
Lists and structs display as JSON in the cell. Top-level nested columns appear as GROUP in the schema view.
Big integers and dates
INT64 values render as exact decimal strings. TIMESTAMP values render in ISO 8601.
Not supported
Modular encryption (Parquet encryption spec), remote URLs, and SQL queries. For those, reach for DuckDB or pandas.
Dependencies
Built on hyparquet. Pure JavaScript, no WebAssembly runtime, no server component.
Questions

FAQ.

Is my file uploaded anywhere?
No. The parser runs inside your browser tab as JavaScript. No request is made to any server with your file contents. You can confirm this by opening your browser DevTools Network panel, dropping a file, and watching that no outbound request is made beyond the initial page and script loads.
How large a file can I open?
The browser streams byte ranges from the file on disk, so file size itself is rarely the limit. In practice, multi-gigabyte files open fine for schema and paginated browsing. The filter feature needs all rows in memory and is capped at 200,000 rows to avoid crashing the tab.
Which browsers are supported?
Any modern evergreen browser. Tested on recent Chrome, Edge, Firefox, and Safari. Internet Explorer is not supported.
Can I inspect parquet files from Microsoft Fabric or OneLake?
Yes, if you can download the file locally first. The tool does not connect to remote storage accounts. Download the file from OneLake, S3, ABFS, or wherever it lives, then drop it into the tool.
Why are my nested columns not expanded?
This tool prioritizes fast schema inspection for flat and lightly nested files. Deeply nested lists and structs display as JSON in cells rather than exploding into separate views. For real nested drill-down, consider DuckDB or Apache Arrow-based viewers.
Can I query the file with SQL?
Not in this tool. For SQL over parquet in the browser, use DuckDB-WASM.
